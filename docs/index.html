The problem

Working across platforms shouldn't feel like smuggling

If your day spans more than one operating system, you know the drill: getting a simple piece of text or a file from one machine to the other is somehow still hard in 2026.

Your devices don't speak the same language

You write code on a Mac and test on Windows. You read on your phone and work at a desk. Every ecosystem has its own transfer tool — AirDrop only talks to Apple, Nearby Share only to Android and Windows — so moving an error log, an API key, or a build artifact across the fence means USB sticks, cloud drives, or retyping it by hand.

The message-yourself workaround

So you email yourself. Or keep a WhatsApp chat with yourself. Or paste snippets into a cloud note. It works — but every private link, password, and document takes a round trip through someone else's server, just to travel two meters across your desk.

ClipboardSS takes the detour out: your devices talk directly to each other.

How it works

Paired in thirty seconds. Encrypted forever after.

No sign-up form, no QR-code app, no cloud handshake. Two devices, one code.

1

Join the same Wi-Fi

Devices find each other automatically with Bonjour — and if your network blocks it, a built-in subnet scan finds them anyway.

2

Type the 6-digit code

One device shows a short-lived pairing code; you type it on the other. That's the whole ceremony.

407 213
3

Keys, not trust

The code seals an X25519 key exchange. From then on, every clip and every file chunk is encrypted with ChaCha20-Poly1305 — a key only your two devices hold.

Privacy

There is no cloud

Not "encrypted in the cloud." Not "we don't look at your data." There is simply no server in the architecture for your data to visit.

No account, no server

Nothing to sign up for and nothing to breach. Your devices authenticate each other directly with keys created at pairing.

End-to-end encrypted

X25519 key exchange at pairing, ChaCha20-Poly1305 on every clip and file chunk. Even on your own network, traffic is sealed.

Verifiable, not promised

The apps, the crypto, and the wire protocol are open source with cross-platform test vectors. The claims above are checkable, not marketing.

Offline by default

History, search, OCR and editing all run 100% locally. The network only comes into play when you pair devices — and then only your LAN.

No telemetry

The apps phone home to no one. No analytics, no crash uploaders, no "anonymous usage statistics."

Free, funded by users

No paid tier collecting your data to subsidize the free one. If it helps you, you can sponsor development — that's the whole business model.

FAQ

Fair questions

Does my data ever touch the internet?

No. Clipboard history, OCR and editing run entirely on-device. Sync and file transfer travel only across your local network, encrypted end-to-end. There is no relay server, no cloud storage, and no telemetry endpoint in the codebase — you can verify that yourself.

Can I sync over the internet, away from home?

Not today, and that's a deliberate design choice: no server means nothing to trust and nothing to breach. Devices must be on the same network (an office LAN or a phone hotspot both work).

What if my network blocks device discovery?

Discovery uses Bonjour/mDNS first. On networks that block multicast (some offices, some routers), ClipboardSS falls back to a quick scan of your subnet, and paired devices remember each other's addresses.

Which OS versions are supported?

macOS 13 or later, Windows 10 build 19041 or later, plus the Flutter companion on current Android and iOS. On iOS, sending is manual via the share sheet (iOS doesn't allow background clipboard monitoring — no app can do it).

Is it really free?

Yes — free and open source, with no paid tier and no data-funded business model. Development is funded by donations via GitHub Sponsors.

How do file transfers stay safe?

Files travel in encrypted chunks — each one sealed with ChaCha20-Poly1305 under a key derived for that transfer — and the whole file is verified against a SHA-256 hash on arrival. A corrupted or tampered transfer is rejected, not saved.
